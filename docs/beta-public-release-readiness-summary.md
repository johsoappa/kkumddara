## 6. 쿠폰 기능 후속 과제

### 쿠폰 기능 현재 판정

현재 베타 무료 이용 단계에서는 쿠폰 입력 UI를 구현하지 않는다.

쿠폰은 실제 결제 금액 할인과 연결되어야 하므로, PG 연동 직전 또는 결제 시스템 설계 단계에서 구현한다.

현재는 결제 금액, PG 연동, 구독 상태 변경, 환불 기준, 쿠폰 할인 적용 방식이 확정되지 않았으므로 쿠폰 기능을 먼저 구현하지 않는다.

### 쿠폰 기능 권장 구현 시점

쿠폰 기능은 정식 유료 결제 오픈 전, 요금제·결제·환불 정책이 확정된 뒤 구현한다.

권장 순서:

1. 요금제 및 결제 상품 구조 확정
2. PG 연동 방식 확정
3. 결제 금액 계산 로직 설계
4. 쿠폰 정책 설계
5. 쿠폰 DB 설계
6. 쿠폰 입력 UI 구현
7. 쿠폰 적용 가능 여부 검증 API 구현
8. PG 결제 금액에 쿠폰 할인 반영
9. 관리자 쿠폰 관리 기능 구현
10. 쿠폰 적용/실패/만료/중복 사용 테스트

### 쿠폰 기능 필수 요구사항

| 영역 | 요구사항 |
|---|---|
| 쿠폰 입력 UI | 결제 직전 쿠폰 코드 입력 |
| 쿠폰 적용 가능 여부 확인 | 유효성, 만료일, 사용 여부, 플랜 제한 확인 |
| 할인 유형 | 정액 할인, 정률 할인, 무료 개월, 첫 달 할인 |
| 적용 대상 | Basic, Premium, Family, Family Plus 중 적용 범위 설정 |
| 사용 제한 | 1인 1회, 전체 수량 제한, 기간 제한 |
| DB 설계 | coupon, coupon_redemption 테이블 |
| 결제 연동 | PG 결제 금액 계산 전 쿠폰 할인 반영 |
| 관리자 기능 | 쿠폰 생성, 비활성화, 사용 현황 확인 |
| CS 대응 | 쿠폰 적용 실패, 만료, 중복 사용 안내 |

### 쿠폰 DB 설계 초안

> ⚠️ 이번 작업에서는 migration을 생성하지 않는다. 정식 결제 오픈 전 설계 초안으로만 기록한다.

**coupon 테이블 후보**

- id
- code
- name
- discount_type
- discount_value
- applies_to_plan
- starts_at
- ends_at
- max_redemptions
- per_user_limit
- is_active
- created_at
- updated_at

**coupon_redemption 테이블 후보**

- id
- coupon_id
- parent_id
- subscription_id
- redeemed_at
- discount_amount
- payment_id

주의:

- 이번 작업에서 DB 생성 금지
- 이번 작업에서 migration 생성 금지
- 이번 작업에서 쿠폰 입력 UI 생성 금지
- 이번 작업에서 결제 금액 계산 로직 수정 금지

### 쿠폰과 베타 초대코드 구분

| 구분 | 목적 | 구현 시점 |
|---|---|---|
| 쿠폰 | 결제 금액 할인 | 정식 결제 오픈 전 |
| 베타 초대코드 | 베타 참여자 식별 또는 접근 제어 | 필요 시 베타 운영 중 |
| 프로모션 코드 | 마케팅 캠페인 추적 | 마케팅 운영 단계 |
