# 직업 콘텐츠 표준 축 정의서

> 관련 구현: [src/components/explore/DreamMapHub.tsx](../src/components/explore/DreamMapHub.tsx), [src/components/explore/DreamMapExtraInfo.tsx](../src/components/explore/DreamMapExtraInfo.tsx), [src/app/explore/[id]/page.tsx](../src/app/explore/[id]/page.tsx)
> 1차 적용 대상: 웹툰 작가 (`webtoon-artist`) 1개, feature flag 기본값 OFF

## 1. 작업 목적

직업 상세 화면(`/explore/[id]`)은 직업 설명·역량·활동·전망·부모 안내 등 텍스트가 누적되며 모바일에서 핵심 정보의 우선순위가 드러나지 않는 문제가 있었다. 이 문서는 텍스트를 축약하거나 삭제하지 않고, **정보를 4개 축으로 접어두었다가 사용자가 선택한 것만 펼쳐 보여주는** 표준을 정의한다. 마인드맵형 UI(꿈 지도)는 이 축이 실제 화면에서 작동하는 참조 구현일 뿐, 축 정의 자체가 1차 산출물이다.

## 2. 콘텐츠 탭 4개 정의

| 탭 | 정의 | 포함 | 미포함 |
|---|---|---|---|
| 하는 일 | 직업에서 실제로 수행하는 핵심 업무 | 직업 한 줄 소개(one_liner/description), 쉬운 설명(easy_description) | 전망·연봉·학과 등 미래 지표 |
| 필요한 힘 | 직업 활동에 도움이 되는 역량·태도·협업 방식 | 심화 시드 `goodFit`, 정적 `skills` 배지 | 관심 분야 코드(IT/예술 등 카테고리 태그) |
| 하루 모습 | 하루 업무 흐름, 작업 환경, 만나는 사람, 활동 장면 | 심화 시드 `dayInLife` | — |
| 해보기 | 학생이 직접 수행할 수 있는 간단한 체험 또는 활동 | 심화 시드 `missions`, 기존 `mission_hint`/`step_action`/`preparations` 체크리스트 | — |

탭 제목은 모바일 최대 7자, 태블릿·데스크톱 최대 12자를 넘지 않는다. 4개 고정이며 임의로 늘리지 않는다.

## 3. 다음 미션 CTA 정의 (탭이 아님)

`다음 미션`은 콘텐츠 탭이 아니라 **다른 화면(로드맵/미션)으로 이동하는 독립 전환 CTA**다. `role="tab"`으로 구현하지 않고 `tablist` 밖에 배치하며, 화면당 이 목적의 CTA는 1개만 유지한다. 이번 구현에서는 기존 하단 고정 CTA("이 직업으로 로드맵 만들기")와 목적이 완전히 같으므로, 꿈 지도 활성 시 하단 고정 CTA를 숨기고 허브 내부의 독립 CTA(`{직업명} 미션 시작하기`)로 대체했다 — 두 CTA를 동시에 노출하지 않는다.

## 4. 미래 지표성 콘텐츠 처리 기준

전망·연봉·성장률·관련 학과·관련 직업 등 미래 지표성 콘텐츠는 5번째 탭으로 승격하지 않는다. 일부 직업은 해당 데이터가 미작성 상태이므로, 탭 승격은 `dream_map_extra_content_opened` 계측으로 열람률을 관찰한 뒤 2차에서 데이터 기준으로 판단한다. 1차에서는 전량 "추가 직업 정보 영역"에 원문 그대로 유지한다.

## 5. 추가 직업 정보 영역 처리 기준

4탭에 대응하지 않는 기존 문장(관심 분야 태그, 고용24 정보, 관련 학과, 관련 직업 더보기, 직업 전망, 퀴즈 등)은 삭제하지 않고 일반 문서 흐름 하단에 배치한다. `position: fixed`/`sticky`를 사용하지 않으며, 기본 접힘 + "더 알아보기" 토글로 펼친다(`DreamMapExtraInfo` 컴포넌트).

## 6. 비진단·법적 고지 배치 기준

비진단·법적·AI 생성 콘텐츠 고지는 접거나 삭제하지 않고 항상 펼친 상태로 유지한다. 착수 전 조사 결과 `/explore/[id]`에는 이런 고지가 기존에 존재하지 않았으므로, 이번에 신규 작성했다(카피 재작성 금지 원칙은 *기존 문장*에 적용되며, 최초 고지 문구 작성은 필수 요구사항이라 예외로 다룬다). 문구는 `src/app/explore/[id]/page.tsx`의 `DREAM_MAP_NOTICE` 상수 참고.

## 7. 문장 목적지 매핑 원칙

기존 문장은 반드시 다음 중 하나에 배정한다: ① 기본 상세 패널(4탭) ② 더 알아보기 접힘 영역 ③ 추가 직업 정보 영역 ④ 비진단·법적 고지 상시 노출 영역. 목적지를 정하지 못한 문장은 삭제하지 않고 "미배정"으로 별도 보고한다(웹툰 작가 기준 미배정 문장 없음 — 12장 매핑표 참고).

## 8. 모드별 적용 기준

**나침반 모드는 현재 코드에 판별 로직이 없다.** `docs/target-child-mode-definition.md`가 나침반 모드를 초5~고등으로 정의하지만, 이를 계산/분기하는 실제 코드는 존재하지 않으며 `/explore`는 애초에 인증·모드 구분 없이 전원에게 동일 콘텐츠를 노출하는 완전 공개 페이지다. 이번 프로토타입은 이 사실에 근거해 **feature flag ON + 직업 slug 화이트리스트**만으로 게이팅하며 mode 조건을 넣지 않았다. 이는 기존 화면과 노출 대상이 동일하므로 안전한 최소 범위 대안으로 판단했다(OZ.대표 확인 완료).

씨앗(초1~2)·새싹(초3~4) 모드 화면은 이번 범위에서 완전히 제외한다. 나침반 모드를 실제로 판별하는 로직(학년 값 기반 계산, 저장 위치, 분기 지점 등)은 이번 작업 범위 밖이며, 별도 설계 과제로 남긴다.

## 9. 나침반 모드 초5~고3 확장 방향 (향후, 이번 범위 아님)

문서 정책상 목표 범위는 초5~고3이다. 확장 전 필요한 것: ① mode 자동 판별 로직 설계·구현 ② 중2~고3 학년별 콘텐츠 난이도 차등화 원칙 수립 ③ 학년별 분기가 온보딩/학생홈/직업탐색/로드맵/명따라/부모리포트/XR 전 영역에 미치는 영향 조사. 이번 프로토타입은 학년별 콘텐츠 분기를 구현하지 않았고 기존 콘텐츠를 그대로 사용했다.
