# 꿈따라 B2B 학부모 동의 흐름 설계

## 5-1. 핵심 원칙

```text
원생 등록 ≠ 데이터 수집.
학부모 동의 완료 시점에만 좌석이 활성화되고, 그때부터 데이터가 쌓인다.
```

## 5-2. 동의 흐름 5단계

```text
[1] 원장이 원생 추가 → 상태: 미활성, 동의 전 최소 정보만 임시 저장
[2] 시스템이 학부모에게 동의 요청 발송 → 카카오/문자/이메일 링크
[3] 학부모가 동의 페이지 확인 → 무엇을·누가·왜 보는지 고지
[4] 학부모 동의/거부
    동의: 좌석 활성화 + 진로 탐색 시작 + 데이터 수집 시작
    거부/무응답: 좌석 비활성 유지 + 데이터 수집 0
[5] 동의 철회 → 즉시 데이터 수집 중단 + 학원 열람 차단 + 자녀 개인 무료 이용은 유지
```

## 5-3. 동의 전 수집 가능 정보

```text
원생 이름 또는 별칭 / 학년 / 학부모 연락처 / 학원 내부 식별용 메모
```

동의 전 미수집:

```text
진로 탐색 기록 / 관심 직업 / 미션 활동 / 명따라 결과 / AI 상담 기록 / 리포트 결과
```

## 5-4. 학원이 볼 수 있는 정보 (동의 후)

```text
진로 탐색 진행률 / 마지막 활동일 / 관심 직업 / 미션 완료 현황 / 상담 필요 상태
```

## 5-5. 학원이 볼 수 없는 정보

```text
자녀 개인 메모 / AI 상담 원문 / 학부모·자녀 개인 대화 / 민감정보 / 광고 목적 관심사 데이터
```

## 5-6. 동의 문구 초안

```text
[필수] 자녀의 진로 탐색 활동 정보를 ○○학원이 열람하는 것에 동의합니다.
[필수] 만 14세 미만 자녀의 경우, 법정대리인으로서 동의합니다.
[선택] 학원이 진로 상담 리포트를 학부모에게 공유하는 것에 동의합니다.
```

## 5-7. 동의 상태 머신

```text
pending → (학부모 동의) → approved → 데이터 수집·학원 열람 ON
pending → (거부/무응답) → rejected → 데이터 수집·학원 열람 OFF
approved → (철회) → revoked → 즉시 열람 차단 / 자녀 개인 이용 유지
```

## 5-8. 개발 원칙

```text
org_id 기반 RLS / 학원은 자기 원생만 열람 / approved 원생만 학원 화면 노출
철회 시 즉시 학원 열람 차단 / 하드코딩 UUID 금지 / slug·FK 기반 / 광고 목적 관심사 활용 금지
```

## 5-9. B2B Lite 단계 고지

```text
현재 B2B Lite 단계에서는 실제 동의 시스템을 구현하지 않는다.
실제 원생 데이터도 수집하지 않는다.
academy 페이지와 demo 섹션은 샘플 데이터만 사용한다.
실제 동의 시스템은 파일럿 학원 확보 후 organizations, parent_consents 등 실제 DB 설계와 함께 구현한다.
```
