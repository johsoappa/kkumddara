# 꿈따라 베타 운영 관리 가이드

> 작성일: 2026-05-30  
> 작성 기준: 베타 공개 가능 판정 후 운영 단계 진입 기준  
> 목적: 기능 확장이 아니라, 실제 사용자 유입 이후 안정 운영을 위한 체계 정립

---

## 1. 운영 목적

꿈따라 베타 운영의 목적은 완벽한 정식 서비스를 즉시 출시하는 것이 아니라,
실제 학부모와 학생 사용 흐름에서 **오류, 이해도, 재방문 가능성, 유료 전환 가능성**을 확인하는 것이다.

### 핵심 방향

| 원칙 | 의미 |
|---|---|
| 기능 확장보다 안정성 | 새 기능보다 현재 기능이 제대로 동작하는지 먼저 확인한다 |
| 사용자 반응 기반 개선 | 가정이 아니라 실제 피드백으로 결정한다 |
| P0/P1 우선 대응 | 핵심 흐름이 막히면 다른 작업보다 우선 처리한다 |
| 핵심 컨셉 유지 | `아직 꿈이 없어도 괜찮아요. 좋아하는 것에서 직업을 찾아요.` |
| AI 중심 아님 | AI는 진로를 찾아주는 중심 기능이 아니라 참고용 베타 보조 기능이다 |

## 8. P0 / P1 / P2 이슈 분류 기준

### P0 — 즉시 수정 (발견 즉시 작업지시서 작성)

- 사이트 접속 불가
- 로그인/인증 흐름 전체 차단
- `/explore` 접근 불가
- `/roadmap` 접근 불가
- `/myeonddara` 접근 불가
- 개인정보·문의 페이지 접근 불가
- 잘못된 이메일/카카오채널 URL 노출
- 명따라 Phase 2 의도치 않은 활성화
- AI가 진로 확정·보장 표현 사용
- 결제 미오픈인데 결제 가능처럼 보이는 문구
- 사용자 데이터 누출 가능 상황

### P1 — 빠르게 수정 (주 1회 검토 후 수정 작업지시서 작성)

- 특정 카드 클릭 시 어색한 화면 이동
- 특정 직업 로드맵 미션 문구 어색
- 모바일 레이아웃 일부 깨짐
- 빈 데이터 안내 부족 (비어있는 화면)
- AI/명따라 문구 부담 (확정·예측 표현)
- 정책 문구 불명확 (환불·요금·베타 안내)
- 부모 리포트 이해도 낮음
- 학부모/학생 체험하기 흐름 끊김

### P2 — 추후 개선 (운영 여유 시 처리)

- 디자인 디테일
- 카드 간격·색상 개선
- 문구 톤 세밀 개선
- 추가 직업 확장
- 그래프·차트 고도화
- PDF 리포트
- 푸시 알림
- B2B 관리자 기능
- 공공데이터 실제 API 연동
- 결제 고도화
